# 정지 의도 감시와 DWA 통로 판정 진단 설계

## 목표

2026-08-23 실주행에서 반복된 비대칭 정지와 자동 수동 모드 전환의 원인을
하드웨어 명령 계층에서 해결하고, DWA가 장애물 때문에 통로를 통과할 수 없다고
판정할 때 그 근거를 bag과 상태 토픽에 남긴다.

이번 변경은 다음 네 결과만 만든다.

1. NUC에만 있는 실측 바퀴 속도 기반 정지 램프를 저장소의 기준 구현으로 옮긴다.
2. 정지 감시기는 바퀴 명령의 `S/S` 바이트가 아니라 `/cmd_vel_gated=0`이라는
   안전 정지 의도부터 감시한다.
3. 감속 불이행과 한쪽 바퀴만 남아 생기는 피벗을 구분해 감지하고
   `/mode_cmd=77`을 발행한다.
4. DWA 거부 시 밴드, 주행 가능 마스크, 장애물 여유 중 어느 단계가 후보를
   제거했는지 기록한다.

## 범위 밖

- 사람 라벨을 이용한 회피 정책 변경
- `DWA_WAIT` 해제 히스테리시스
- 저속 조향 제한 또는 DWA 점수/각속도 조정
- 장애물 여유 `0.40 m`, 안전 밴드, 주행 가능 마스크 완화
- 다단 곡률 또는 새로운 전역·지역 경로 계획 알고리즘
- 이 작업 중 NUC 실행 작업공간을 직접 덮어쓰거나 주행 노드를 재시작하는 작업

## 근거

### 정지 계층

`blackbox_20260823_212210.bag`에는 정지 불이행 경보가 14건 있다. 그중 9건은
한쪽 바퀴가 `0.36~0.58 m/s`로 남아 발생한 피벗이다. 모든 경보에서 UART의
`tx_fail`과 `tx_slow`는 0이었다. WP1216 사례에서는 왼쪽이 정지한 상태에서
오른쪽이 `0.361 m/s`로 남아 약 `38 deg/s`로 회전했고, `/stop_watchdog`가
`/mode_cmd=77`을 발행했다.

현재 NUC의 `~/catkin_ws/src/base_model/src/wheel_cmd_tmp.py`는 실측 좌우 속도를
각각 감속한 뒤 `0.06 m/s` 아래에서만 `S`로 전환한다. 그러나 이 구현은 GitHub
`main`의 `tools/base_model_wheel_cmd_guard.py`에 없고 테스트도 없다. 반대로 현재
`stop_watchdog.py`는 양쪽 바이트가 이미 `S/S`일 때만 감시를 시작하므로 새 램프의
감속 구간을 감시하지 못한다.

### DWA 통로 판정

가장 최근 두 bag을 비교한 결과는 다음과 같다.

- 최신 bag의 `DWA_OBSTACLE`은 WP1216에서 0.151초 한 번 발생했다.
- 당시 밴드 폭은 `2.05 m`였다.
- 동일 자세와 장애물 프로필을 현재 `main`의 DWA로 계산하면 후보 105개 중
  50개가 밴드, 마스크, `0.40 m` 장애물 여유를 모두 통과한다.
- 바로 이전 bag에는 `DWA_OBSTACLE`과 장애물에 의한 `DWA_OFF_BAND`가 없다.
- 이전 bag의 93초 `DWA_SPEED_BELOW_FLOOR`는 통로 폭이 아니라 실행 불가능한
  저속 접근 상한 문제이며 현재 `0a6db80`에서 수정돼 있다.
- 최신 bag의 122초 `OFF_BAND`는 폭 `1.60 m` 구간에서 차체 중심이 경로에서
  `0.727 m` 벗어난 실제 밴드 이탈이다.

따라서 최근 기록은 안전 여유를 줄이거나 장애물을 삭제할 근거가 아니다. 현재
`main`이 통과시키는 WP1216 장면을 회귀 픽스처로 고정하고, 다음 거부가 발생하면
단계별 후보 수로 실제 원인을 바로 판별한다.

## 구조

명령 흐름은 그대로 유지한다.

```text
waypoint/DWA -> /cmd_vel_raw -> safety_gate -> /cmd_vel_gated
             -> tip_guard -> /cmd_vel -> wheel_cmd -> uart -> motor base

                          /cmd_vel_gated -----+
                          /cmd_vel -----------+--> stop_watchdog
                          /wheel_status ------+
                          /uart_tx_diag -------+
                                                   |
                                                   +--> alarm, mode_cmd=77
```

새 토픽이나 메시지 형식은 만들지 않는다. 정지 감시기는 이미 bag에 기록되는
토픽을 함께 읽고, DWA 진단은 기존 `/waypoint_follower/status` 문자열에 붙인다.

## 구성요소 설계

### 1. 실측속도 기반 정지 램프

`tools/base_model_wheel_cmd_guard.py`에 NUC 구현의 순수 함수 두 개를 옮긴다.

- `wheel_speed_mps(direction, magnitude)`는 상태 프레임의 방향과 속도 바이트를
  부호 있는 `m/s`로 변환한다.
- `stop_ramp_command(left_mps, right_mps)`는 좌우 바퀴를 독립적으로 감속한다.

기본값은 현재 NUC에서 사용하는 값을 유지한다.

- `RAMP_DECAY = 0.9`
- `RAMP_BLEED_MPS = 0.09`
- `RAMP_TERMINAL_MPS = 0.06`
- `STATUS_FRESH_S = 0.3`

`WheelCommandGuard`는 최신 `/wheel_status`에서 좌우 실측속도를 보관한다.
최종 `/cmd_vel`이 0이거나 명령이 거부됐을 때 상태가 0.3초 이내면 램프 명령을,
그보다 오래됐으면 기존의 보수적인 `S/S` 명령을 발행한다. caller ID 검증과
fault latch 계약은 변경하지 않는다.

### 2. 정지 의도 상태기계

`StopHonouredCheck`를 바이트 프레임 전용 검사기에서 정지 의도 상태기계로 바꾼다.
ROS와 무관한 순수 클래스는 다음 입력을 시간순으로 받는다.

- `observe_gated_command(linear, angular, now_s)`: safety gate가 요청한 동작
- `observe_final_command(linear, angular, now_s)`: tip guard가 바퀴 계층에 넘긴 동작
- `observe_status(data, now_s, mode)`: 실측 좌우 바퀴 속도와 모드

`/cmd_vel_gated`의 선속도와 각속도가 모두 0일 때 정지 의도가 시작된다. 새 주행
명령이 들어오거나 모드가 AUTO가 아니면 상태를 해제한다. `/cmd_vel`은 tip guard가
아직 정상 감속 명령을 내리는 구간과 최종 0 명령에 도달한 구간을 구분한다.

다음 세 결함을 서로 다른 이유로 한 번만 보고한다.

1. `STOP_NOT_HONOURED`: 최종 `/cmd_vel=0` 이후 0.40초가 지났는데 어느 바퀴든
   `0.15 m/s`를 넘는다.
2. `NOT_SLOWING`: 정지 의도 이후 관측 창 동안 최대 바퀴 속도가 줄지 않아 정상
   감속으로 설명할 수 없다.
3. `ONE_WHEEL_PIVOT`: 한 바퀴는 정지 영역인데 다른 바퀴가 움직여 차축 폭
   `0.54 m` 기준 피벗 각속도가 안전 한계를 넘는다.

피벗은 최종 0 명령을 기다리지 않는다. 정지 램프 중에도 좌우 비대칭이 위험한
수준이면 즉시 검출해야 2026-08-23 사례를 다시 잡을 수 있다. 정확한 감속 관측 창,
속도 감소 허용오차와 피벗 한계는 다음 값으로 고정한다.

- `NOT_SLOWING_WINDOW_S = 0.50`: 정지 의도 시작 속도가 `0.15 m/s`를 넘으면
  0.50초 뒤 최소 `0.05 m/s` 감소해야 한다. tip guard의 정상 감속 상한
  `0.30 m/s²`는 같은 시간에 `0.15 m/s`를 줄이므로 세 배의 여유를 둔다.
- `PIVOT_STATIONARY_MPS = 0.15`, `PIVOT_MOVING_MPS = 0.30`: 한쪽이 정지
  영역이고 다른 쪽이 확실히 움직일 때만 피벗 후보로 본다.
- `PIVOT_YAW_RPS = 0.50`과 `PIVOT_CONFIRM_S = 0.15`: 좌우 속도차를
  `0.54 m` 차축 폭으로 나눈 값이 약 `28.6 deg/s`를 0.15초 유지하면
  결함이다. 기록된 피벗 9건은 모두 `38 deg/s` 이상이다.
- `FINAL_STOP_GRACE_S = 0.40`, `MOVING_MPS = 0.15`: 최종 명령이 0이 된
  뒤의 기존 정지 불이행 기준은 유지한다.

### 3. ROS 감시 노드

`StopWatchdog`는 `/cmd_vel_gated`, `/cmd_vel`, `/wheel_status`, `/uart_tx_diag`를
구독한다. 순수 상태기계가 이유를 반환하면 기존과 같은 JSON alarm을 발행하되
다음 정보를 포함한다.

- 결함 종류와 설명
- 좌우 실측속도와 계산 피벗 각속도
- 정지 의도 후 경과시간
- 마지막 gated/final 명령의 나이
- UART 전송 진단

결함당 `/mode_cmd=77`은 한 번만 발행한다. MANUAL 모드에서는 감시하지 않고,
새 AUTO 진입 후 새 정지 의도가 관측돼야 다시 무장한다.

### 4. DWA 후보 진단

`DwaPlanner`의 반환 형식 `(v, w, status)`는 유지한다. 각 `plan()` 호출은 같은
벡터 계산에서 다음 값을 `last_diagnostics`에 저장한다.

- 전체 후보 수
- 안전 밴드를 통과한 수
- 주행 가능 마스크를 통과한 수
- 밴드와 마스크를 모두 통과한 수
- 장애물 `0.40 m` 여유를 통과한 수
- 모든 조건을 통과한 수
- 유효 후보 중 최소 장애물 여유의 최댓값

추가 검색이나 중복 rollout은 하지 않는다. `DwaFollower`는 계획이 거부됐을 때만
이 값을 `HOLD:DWA_<reason>` 상태 문자열에 붙인다. 기존 상태 접두사는 유지하므로
운영 스크립트와 bag 분석기는 계속 같은 이유를 인식할 수 있다.

## 테스트 설계

### 바퀴 정지 램프

- 정지한 두 바퀴는 즉시 `S/S`가 된다.
- 전진·후진 바퀴는 방향을 유지하며 실측속도보다 낮은 값을 요청한다.
- 좌우 속도가 다르면 독립적으로 감속한다.
- 상태가 오래됐으면 기존 `S/S` fallback을 사용한다.

### 정지 감시

- 좌우가 함께 정상 감속하면 alarm이 없다.
- 한쪽만 정지하고 다른 쪽이 남으면 `ONE_WHEEL_PIVOT`가 한 번 발생한다.
- 양쪽 또는 한쪽이 관측 창 동안 감속하지 않으면 `NOT_SLOWING`이 발생한다.
- 최종 0 명령을 0.40초 넘게 무시하면 `STOP_NOT_HONOURED`가 발생한다.
- MANUAL 모드와 오래된 명령 스트림에는 중복 alarm이 없다.
- 주행 재개와 AUTO 재진입 뒤 새 정지 의도에서 다시 무장한다.

### DWA

- WP1216의 자세, 밴드, 마스크, 6개 장애물 프로필 점을 기록 픽스처로 사용한다.
- 현재 `main`처럼 하나 이상의 후보가 모든 조건을 통과하고 상태가 `OK`인지
  검증한다.
- 벽이 통로를 실제로 막는 장면은 `OBSTACLE`과 `all_ok=0`을 반환한다.
- 밴드만 막는 장면과 마스크만 막는 장면의 후보 수가 해당 단계에서 0이 되는지
  검증한다.
- `plan()`의 기존 3개 반환값 계약이 유지되는지 검증한다.
